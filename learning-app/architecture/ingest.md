# SOP: Ingest (Markdown -> unit JSON)

## Goal
Turn one course source file into `content/<unit>/unit.json` (concepts + questions). Deterministic, no LLM. Source files are never modified.

## Inputs
- A unit definition in `tools/ingest.py` (`UNITS`): id, title, source path, parser.
- Optional diagrams at `content/<unit>/diagrams/<concept-id>.mmd` (hand/Claude-authored, generated once; ingest only attaches them).

## Parser for unit `fw1` (FREE Workshop, Terraform)
Include as concepts:
- `## Quick Revision Map`, `## Essential Terraform Commands` (incl. `### Typical Workflow`), `## Interview Preparation Strategy`.
- Every `###` under `## Core Concepts Covered` (kind `concept`). The `Terraform Key Terminology` section is split into one concept per top-level `- **Term**` bullet.
- Every `###` under `## Hands-On Practicals` (kind `practical`).
Include as questions:
- `## N. Title` + `**Answer:**` (kind `interview`)
- `## Scenario N: Title` + `**Question:**` / `**Answer:**` (kind `scenario`)
Exclude: badges, logistics, participants, roadmap, pricing, Q&A chatter, action items, "Interview Questions Highlighted" (no answers), practice challenge.

## Rules
- Headings inside code fences are ignored.
- Clean artefacts: `****` bold-marker leftovers, trailing spaces.
- Concept id = `<unit>-<slug(title)>` (stable under reordering); question ids `<unit>-q01`, `<unit>-s01`.
- `concept_ids` on a question = up to 3 concepts whose title terms appear in the question prompt (not the answer). Overview/method concepts are never linked.
- IDs must be unique; fail loudly otherwise.

## Edge cases / learnings
(append when something fails)
- Link terms must match on word boundaries ("source" matched "resource"). Found in test_word_boundary_linking.

## Generic parser (all other units) — added 2026-10-26
Used for every class-note file except `fw1` (which has its own parser).

Discovery (`discover()`): per `Session-NN-*` directory, every `.md` except `README.md`, `Interview-QnA.md`, `Scenarios.md` is a note unit. Root-level `Session-41-Ansible-Architect` (no extension), `Session-59-...md` and the `Extra Last Session ... KAFKA` file are note units too. A session with no note units gets one **light unit** from its README. Unit ids: `sNN`, or `sNNa`, `sNNb`... when a session has several units.

Splitting (`parse_generic`): split at `#`/`##` headings (fence-aware).
- Noise sections skipped: Key Outcomes, Action Items, Pending Confirmation, Open Questions, Decisions, Table of Contents, Navigation, Prerequisites, Student Q&A, Interview Tip, batch headers.
- Question sections: headings like `1. …?`, `Q1: …`, `❓ Q1: …`, `Scenario N: …`, at h2 or inside a question container (`### N. …` under a title containing "question"/"scenario"). Answer = body (minus `**Answer:**`); `**Question:**` becomes the prompt for scenarios. Question ids are sequential per unit (`q01`, `s01`).
- Concept sections: every other section; if it has 2+ `###` children each child is a concept, otherwise the section is one concept.
- A section over ~2500 chars with no `###` children and mostly bullets is **flat**: kept as one concept but listed in the unit's `needs_authoring` (a human or Claude must split it).

Light unit (`parse_light`): from README — "Topics covered", "Key learnings" and each `Task-NNN` title. No diagrams or Q&A (README bodies are templated).

Not ingested: `Interview-QnA.md`, `Scenarios.md` (templated), `Mock-Interview/*` (question lists only). `DATA_TODO.md` is regenerated by `ingest.py` and lists everything left to prepare.
